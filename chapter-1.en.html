Chapter 1. Evidence for Learned Target Behavior

We continue training an SFT model with GRPO. Premature action on original email clarification–confirmation paired tasks falls from 19/20 to 0/20, while pre-write lookup on two-tool tasks requiring an additional sharing-policy query falls from 60/60 to 0/60. Success remains 20/20 and 50/60 in the two sets respectively. The same training run improves action order on the original tasks but loses the query order required by the new tasks.

We investigate this question across three training routes, examining success separately from call order and returned-parameter use. After finding behavioral differences, we inspect sampled trajectories, rewards, and the action advantages used for updates. Chapter 6 presents paired trajectories, Chapter 8 examines within-group signals, and Chapter 10 explains the next check for different findings.

1.1 Terminal Outcomes, Training Rewards, and Target Behaviors

A complete trajectory produced by an interaction between an agent and its environment includes the observations received by the model at each step, the actions it emits, and the order of those actions. Training updates the model through a scalar objective, while evaluation summarizes the result using task success or a terminal score. These quantities are produced either by predefined computational rules or by an LLM applying specified grading criteria, retaining only part of the trajectory's information. This report also examines action order and parameter dependencies in complete trajectories, reporting terminal outcomes, training rewards, and target behaviors separately.

Write the trajectory of an interaction as

τ=(o0,a0,o1,a1,…,oT,aT),\tau=(o_0,a_0,o_1,a_1,\ldots,o_T,a_T), τ=(o0​,a0​,o1​,a1​,…,oT​,aT​),

Here, oto_tot​ is the observation the model actually sees before acting at step ttt, and ata_tat​ is the action it then submits to the environment, such as a tool call or page click. The variable xxx denotes the task conditions fixed when the trajectory is generated, including the user request, initial environment state, available action interfaces, and evaluation variant. We compute the following three quantities for the same trajectory:

Y(τ,x)Y(\tau,x)Y(τ,x) The terminal outcome evaluated, such as whether the task was completed, whether the target product was purchased, or the final task score.

The target behavior BBB turns the training intent into a condition that can be checked directly on the trajectory. Here, “write” means a write attempt, including one blocked by the environment. If the trajectory contains a write attempt, the lookup must precede the first attempt. Otherwise, we check whether the lookup occurred. The indicator is 1 when this condition holds and 0 otherwise.

Results in this report come from four kinds of work.

  1. Calculation. Apply an explicit formula to saved data without running the model again.

  2. Counting. Count how often something occurred across tasks, trajectories, or training.

  3. Training. Train models under different settings and compare their behavior afterward. Comparisons with other conditions held equal examine the effect of a specific training change.

  4. Inference. Use a trained model to complete tasks without updating its parameters. Change only the task input or the information returned at one step, then compare the actions it takes afterward.

Each result states exactly what its numerator and denominator count. Different objects are reported separately, with their own denominators.

1.2 Three Experimental Questions

Ask-or-Act Capability and Generalization

We first use the original tasks to check whether the model learned the intended execution procedure, then test tasks with changed information sources, tool dependencies, and business domains. Some tests change two conditions together: the two-tool tasks relocate sharing rules and add numerical judgment. Section 2.3 gives the constructions. Query order, returned-parameter use, and write conditions are judged separately from trajectories.

Retrieval and Use in WebShop

We inspect page visits and returned content to check information acquisition, then compare purchase fields across runs with different text treatments. Section 7.1 specifies how conditions are run, and Section 7.2 checks their prefixes and target products. We also decompose attribute scoring for purchased products to locate matched attributes across pages.

Behavior and Reward in Group-Relative Training

We check whether multiple rollouts for one task contain different target behaviors and whether reward distinguishes them correctly. Under standard GRPO, identical within-group rewards give zero reward-derived advantages. If environment actions are also identical, these trajectories contain no alternative action chain to rescore. With nonzero advantages, we still need to inspect how they enter parameter updates. Post-training behavioral evaluation checks whether those changes make the model meet the target requirements more reliably.

1.3 Three Training Routes

SFT serves two purposes in these experiments. We evaluate SFT models directly to examine the capabilities learned from demonstrations. We also use an SFT model as the starting point for GRPO to examine how continued reinforcement learning changes the learned behavior. In addition, we run GRPO directly from the initial Instruct model and compare it with the route that includes SFT.
