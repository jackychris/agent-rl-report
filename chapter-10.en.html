Chapter 10. Diagnosing Behavior and Training in Agent RL

10.1 Diagnose Training from Behavioral Differences

In the preceding cases, similar task outcomes accompany different action procedures, and added scores produce different training effects. The following sequence organizes the checks used in these cases, with observed behavioral differences guiding the next step.

1. Check whether the target behavior is measured

Read the task requirements, the tool returns received by the model, and the judgment code. To measure returned-handle use, inspect the later call's argument. To measure business completion, inspect terminal state and permitted alternative routes. Both bookings in the scheduling comparison in §6.1 succeed; only one uses the returned handle.

In this example, success measures booking completion, and the internal ledger stores information known to the environment. Comparing the returned handle with the later argument in each trajectory reveals the difference in parameter use between the two successful trajectories.

2. Locate the task conditions under which behavior changed

Pair trajectories for the same task before and after training, separating entity changes, combined requirements, and information relocation. In the email comparison in §6.1, premature action decreases on the original paired tasks and increases on two-tool tasks. Locating where the procedures first diverge in each set helps guide checkpoint selection for the intended task requirements.

Aggregate tables show changes in counts for each task set; paired trajectories show which step the model changes within the same task.

3. Inspect what was actually sampled for the task

Read a group of trajectories from the same run and sampling conditions, comparing target behavior separately from environment actions. If actions repeat, inspect sampling and candidate construction. If actions differ but target behavior does not, identify what changed. If target behavior differs, proceed to reward.

The hair-extension task in §8.1 follows the first branch; the popcorn task already contains action variation. Which flavor better satisfies the task depends on the user's specific request.

4. Check whether reward distinguishes the target behavior

Read unrounded returns, scoring components, and target-behavior labels. When the same target behavior receives different scores, locate the source of the difference. When different behaviors tie, check whether reward includes the target requirement. When worse behavior scores higher, inspect reward direction and competing components.

A candidate reward's ranking is appropriate when behavior that better satisfies the task receives a higher score. This check examines both whether scores differ and which behavioral differences they represent.

5. Calculate the complete advantage assigned to the action

Use the run's actual estimator to calculate episode terms, local terms, and baselines. Check what survives normalization, then identify the action tokens receiving those advantages. A group-constant bonus disappears under centering; a negative local difference in GiGPO can be outweighed by a positive episode difference.

If complete advantages are zero, inspect reward-derived policy loss separately from KL, entropy, and other terms. If advantages are nonzero, inspect clipping, masks, and aggregation. The local reward passes through these calculations to become the signal that acts on training.

6. Compare training signals with behavioral changes

Within one training run, compare the advantage assigned to an action with its selection probability before and after the update, then evaluate the target behavior on the corresponding tasks. The Ask-or-Act group-phi-k0 analysis locates zero-advantage training steps, while the eight-rollout WebShop analysis identifies groups with equal returns and actions. These analyses concern different runs, examining training-time advantages and post-training sample diversity respectively.

Applying both analyses to one training run opens a further question: even when a better action is sampled and receives positive advantage, does it become more frequent in subsequent decisions? This calls for comparing action probabilities under the same task and context and evaluating the target behavior after training, rather than checking only whether advantages are nonzero.

10.2 Conclusions and Open Questions

Execution Procedures and Generalization

The same GRPO continuation reduces premature action on original clarification–confirmation paired tasks from 19/20 to 0/20, while reducing pre-write lookup on two-tool tasks from 60/60 to 0/60. Success remains 20/20 and 50/60 in the two sets respectively. For this run, selecting checkpoints solely on the original tasks would miss the change in lookup order on the two-tool tasks.

Direct GRPO retains pre-write lookup on 58/60 two-tool tasks, but still makes intent errors. On the scheduling handle-binding branch, it completes all 30 tasks while using the returned handle on only six.

We hypothesize that procedures already established in the starting model affect how subsequent training changes action order. This raises two questions: at what stage of training does lookup order begin to change on new tasks, and does that change coincide with improvement on the original tasks?

Visit reward and information use

The visit reward makes WebShop subpage visits nearly universal, and replay confirms that they usually return nonempty content. Task success changes much less. The separate text-treatment runs produce different purchase-field readings, but do not isolate a fixed-prefix observation effect. The attribute decomposition describes matched attributes of purchased products, not the benefit of reading before deciding what to buy.

The change in visitation is clear. A further question about information use is whether changing page content alters the purchase decision when the preceding history and target product are identical, and how visit rewards affect this response.

Behavioral Diversity and Training Signals

In the post-training sampling evaluation of the WebShop model trained with terminal reward only, 197 tasks receive identical scores across eight trajectories, all strictly between zero and one. Although outcomes still leave room for improvement, reward-derived advantages in these groups are already zero. For 121 of these tasks, the runs also repeat identical environment-action sequences. Rescoring these trajectories provides no different actions to compare. The remaining 76 tasks contain different action sequences with equal returns. Before changing their rewards, the relevant question is whether those action differences matter to the task requirements.

The analysis in Chapter 8 also raises an open question about the training mechanism: does an action receiving positive advantage become more likely after the update? How updates for different actions interact and affect subsequent choices deserves further study. Tracking action probabilities within the same task could help explain why target behavior may stall even when a training signal is present.

By comparing trajectories on concrete tasks, this report locates action differences behind terminal success and distinguishes tied candidate groups with identical actions from those with different actions.
