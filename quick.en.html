Scores and Behavioral Evidence in Agent Reinforcement Learning

Author: Hao Fu

From Task Scores to Agent Behavior

A behavioral study of Qwen3-8B on Ask-or-Act and WebShop.

Which behaviors improve when the training score rises? We compare supervised fine-tuning (SFT), Group Relative Policy Optimization (GRPO) after SFT, and direct GRPO on Ask-or-Act, then examine visit rewards and within-group training signals on WebShop.

Action Order on Original and Modified Tasks

We train with SFT on 192 demonstration trajectories and then continue with GRPO. Training success on the original email tasks rises from 178/192 to 192/192. Both checkpoints complete all 20 clarification-confirmation paired tasks (ten controls and ten combined tasks). Premature write attempts fall from 19/20 to 0/20, where a premature action means attempting a write before its task conditions hold, including environment-blocked calls.

The pattern reverses on another set of email tasks. Original file queries return sharing rules directly. The modified two-tool tasks split file size and sharing thresholds across two calls, so the model must query both before deciding. Both checkpoints succeed on the same 50 of 60 tasks. The count satisfying the pre-write policy query condition falls from 60/60 to 0/60. Ten of the 60 SFT runs query the policy and end before any write attempt.

We trace one 4 MB task where approval starts above 10 MB and sharing stops at 25 MB, omitting identical initial queries:

Query sharing policy → request confirmation → send succeeds → finish

Both checkpoints also request confirmation unnecessarily on this task. Continuing GRPO removes premature writes on the original pairs and replaces the pre-write policy query with a post-block retry on two-tool tasks.

Behavioral Differences Across Three Training Routes

We compare SFT, GRPO after SFT, and direct GRPO from the initial Instruct model. Direct GRPO satisfies the pre-write policy query condition on 58/60 two-tool tasks, and triggers premature action on all 60 tasks. In 28 tasks, that flag comes solely from invoking an operation that mismatches the request, such as creating a draft when asked to send an email.

Scheduling reveals a parameter-passing split. A group query returns an owner identifier needed by the subsequent member query. Direct GRPO completes all 30 tasks requiring this dependency, and passes the returned identifier in six. In a typical trace, the model passes a group identifier, hits a blocked call, asks the user for the owner identifier, and completes the booking.

Tied Returns and Repeated Actions

We sample eight rollouts at temperature 1.0 across 500 WebShop tasks from the terminal-reward GRPO checkpoint. On 197 tasks, all eight rollouts earn the same score strictly between 0 and 1. Room to gain score remains on those tasks, and standard GRPO gives them zero reward advantage. All eight environment-action sequences are also identical on 121 of those 197 tasks.

The remaining 76 intermediate tied tasks contain distinct actions. For these tasks, determine whether the action differences matter to task requirements, and check whether the reward assigns distinct scores to those differences. Tasks with identical actions across eight samples need different candidate rollouts, since rescoring identical paths yields identical updates. Once rewards diverge, trace the normalized action advantage that enters optimization.
